`0.6.0` 是分叉后的首个版本：包名改为 `dsh-ops-pro`，并汇总了自 `v0.5.5` 以来吸收的上游修复与本分叉自己的改进。

<h3 id="cn-v0.6.0">破坏性变更</h3>

- npm 包、插件行与清单 id 改为 `dsh-ops-pro`。从 `dsh-ops` 迁移：先移除 `dsh-ops`，再 `dsh plugin add dsh-ops-pro`；旧行的设置不会自动迁移。状态目录 `<DSH_HOME>/dsh-ops/` 与 `ops_` 工具前缀保持不变。

<h3 id="cn-v0.6.0-fixes">问题修复</h3>

- 统一通过一个 helper 解析 cordis 根上下文，兼容以 `Symbol.for('cordis.root')` 存放根的新宿主（上游 #1026）。
- 卸载后残留的默认模式在下次激活时修复（#881/#928）。
- 批量指引改为在第一个根 `run_code` 结果里教一次，并按会话限制形状提示为 3 条（#1027、上游 #1008 方向）；只列出作用域实际发布的文件 API。
- 发现区段在工具选择前后字节不变，避免提示词缓存失效（#975）。
- Windows：发布重命名对端点安全造成的瞬时拒绝做有界重试；忽略 `$KERNEL.PURGE.*` 扩展属性；修正 `STATUS_NO_MORE_EAS` 常量；从注册表发现 Git for Windows（#803）；Niubash 下给出真正能脱离的后台启动方式（#798）；未知运行时打开失败时提示可能被安全软件隔离（#771）。
- 吸收上游 PR：#977、#938、#1007、#930、#961、#1004、#964、#1029、#965、#1002、#1003、#1005、#1006、#802、#743（linux-arm64 本机 staged）、#1019、#1011/#1013/#1014（测试与 bench）。

<h3 id="cn-v0.6.0-ops">维护</h3>

- 移除内部兼容转发模块；`npm run sync:upstream` 报告未吸收的上游提交与 PR；打 tag 的发布可经 npm Trusted Publishing 发布。

`0.6.0` is the first release of the fork: the package is now `dsh-ops-pro`, and it collects the upstream fixes absorbed since `v0.5.5` together with this fork's own changes.

<h3 id="en-v0.6.0">Breaking Changes</h3>

- The npm package, plugin row and manifest id are now `dsh-ops-pro`. To migrate from `dsh-ops`, remove it first, then `dsh plugin add dsh-ops-pro`; settings of the old row are not migrated. The state directory `<DSH_HOME>/dsh-ops/` and the `ops_` tool prefix are unchanged.

<h3 id="en-v0.6.0-fixes">Bug Fixes</h3>

- Resolve the cordis root through one helper, so hosts that key it at `Symbol.for('cordis.root')` work (upstream #1026).
- Repair a stranded default mode left by uninstall on the next activation (#881/#928).
- Teach the batching lesson once on the first root `run_code` result and cap shape notices at three per session (#1027, direction of upstream #1008); the lesson names only the file APIs the scope publishes.
- Keep the discovery section byte-identical across tool selections so the prompt cache survives (#975).
- Windows: retry transient endpoint-security denials of publishing renames within a bound; ignore `$KERNEL.PURGE.*` extended attributes; correct `STATUS_NO_MORE_EAS`; offer Git for Windows from its registry path (#803); name a launch that actually detaches under Niubash (#798); point unknown runtime open failures at endpoint-security quarantine (#771).
- Absorbed upstream PRs: #977, #938, #1007, #930, #961, #1004, #964, #1029, #965, #1002, #1003, #1005, #1006, #802, #743 (locally staged linux-arm64), #1019, #1011/#1013/#1014 (tests and bench).

<h3 id="en-v0.6.0-ops">Maintenance</h3>

- Retire the internal compatibility re-exports; `npm run sync:upstream` reports unabsorbed upstream commits and PRs; a tagged release can publish to npm through Trusted Publishing.

**Based on**: upstream [T-Auto/dsh-ops v0.5.5](https://github.com/T-Auto/dsh-ops/releases/tag/v0.5.5)
