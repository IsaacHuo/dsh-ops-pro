# 手动验收

English: [manual acceptance](manual-validation.md)。下面的 1.1.0 清单是当前发布清单；其后的 0.4.0 清单作为历史记录保留。以下是操作者检查清单，不代表每种 UI 或部署均已验证。使用一次性 profile 和工作区，记录命令、实际结果、平台/宿主版本及候选 commit。

## 1.1.0 电脑操控（当前）

在真实 Windows 10/11 x64 桌面上执行。本清单没有任何一项由 CI 覆盖：仓库套件只在上游单元测试里用 mock 验证，不接触真实桌面。每步记录系统版本、DSH 版本、commit 与截图。

1. **安装与身份**：一次性 profile 中执行 `npx --yes dsh-ops-pro@latest install --profile desktop`，启动宿主，确认只有一行、id 为 `dsh-ops-pro`、版本 1.1.0；`dsh-ops-pro status --profile desktop` 结果一致。computer-use 关闭时不应出现任何 `ops_cu_*` 工具。
2. **启用**：开启 computer-use 行并重启，确认 26 个 `ops_cu_*` 工具出现；再次关闭后工具消失，且没有残留子进程（用 `tasklist` 核对）。
3. **桌面识别**：打开一个普通 Win32 程序（记事本即可）。`cu_snapshot` 与 `cu_accessibility_tree` 返回元素树；`cu_find` 按名称找到菜单项，`cu_invoke` 触发它。全程不移动鼠标：通道在后台工作，操作后指针位置必须不变。
4. **元素 id**：复用第 3 步的 id 调用 `cu_element_info` 并执行一次动作；再切到另一窗口后返回，确认过期 id 被拒绝，而不是作用到错误元素。浏览器通道中 `cu_set_value` 指定 `elementId: "new-tab"` 会打开新页面。
5. **审批与拒绝**：触发需要审批的动作（例如 `cu_focus` 后对输入框 `cu_type_text`），确认审批提示写明动作与目标；拒绝一次并确认没有输入任何内容。提示与报告都不得出现凭据值。
6. **浏览器通道**：用一次性 profile 启动浏览器通道，打开一个站点，读取可访问性大纲，用 `cu_set_value` 填写字段后关闭。再设置 `browserAttachUser`，确认附加到用户自己的浏览器需要显式审批与远程调试，且插件不会自行登录。
7. **故障恢复**：杀掉一次 computer-use 子进程，确认自动重启；一分钟内再杀一次，确认工具报 `CU_UNAVAILABLE`，而不是静默重试。工具超时报 `CU_TIMEOUT`，不留半执行动作。
8. **侧边栏控制台**：打开电脑操控页签，修改一个设置，确认写入 `<DSH_HOME>/dsh-ops/computer-use.json` 且只重启 computer-use 运行时；状态页显示的内容与 CLI 一致。
9. **用量统计**：执行若干工具调用，核对调用数、失败数、墙钟时间 p50/p95 与估算 token 数；`resetUsage` 清零，且 `<DSH_HOME>/dsh-ops/usage.json` 始终是合法 JSON。
10. **卸载**：卸载并重启，确认没有 `ops_cu_*` 工具、没有子进程，且 `computer-use.json` 与 `usage.json` 保留以便回滚。

## 0.4.0 清单（历史）

## 构建与发布证据

按[贡献指南](贡献指南.md)构建 worker，并在 Windows 提供已校验 Bash fixture，运行完整发布门禁；所需运行时被跳过不能计为通过。单独运行[BM-01–05](基准门禁.md)，保留逐项通过/失败/阻塞状态与原始结果。采用明确批准的标准：BM-01 在固定无损工作负载上相比 OPS 0.3.x 至少减少 40% 字节，官方读取另列对照；BM-03 对文件/发现 schema 执行 ≤400 token 上限，并保留 Bash 启动常驻。同时记录范围分数与完整供应商总数，核验含可用 Bash（Windows 固定载荷或宿主 bash）的确切默认工具清单。不能用更小工作负载、缺少 Bash 或功能 CI 通过代替实测。

## Profile 与配置

1. 用含带名称覆盖、混合开关和其它插件配置的已保存六行 profile 升级并重启两次；确认七个唯一 OPS ID、旧文件行名称与配置、显式开关均保留，并新增 discovery。
2. 新 profile 默认 file/PTC/discovery 开，三个平台的 shell 都开，panel/TUI/替换关。启用新 panel 行后观察新事件；关闭后排队采集停止，不执行最终归并。旧配置显式 capture:false 必须保持不采集，直到操作者更改。
3. 内置表单保存合法值后重启验证；未知键、错误类型或过期版本不覆盖已保存值。旧 file/root/shell 的 null 配置保持原默认值。关闭的行先开启才可编辑。

## 工具发布与结果

1. 检查首次实际供应商请求：Standard/Cordis Native 有 inspect_local_file/glob/grep、discover_tools 及可用的 Bash，read_files/result 与高级文档 schema 不可见。发现后仅所属下一请求可见，当前轮诊断或兄弟 agent 不可见。
2. PTC 常驻 inspect_local_file/load_sdk；result 按需加载，allowedTools 为空也可选择。通过 ops_load_sdk 加载允许的高级 API，核对下一 SDK 快照及类型化 Outcome 的 status/data。保留操作者显式允许池；工具可见不代表授予文件权限。
3. 一次读取三个文件范围，精确还原转义行，核对逐文件错误、待处理输入与文件内续读。一个文件五处编辑使用修订值；过期 CAS 或重叠编辑不得更改内容，部分输出不得冒充完整。
4. 读取 CSV/TSV、DOCX 和受支持 PDF 文本层，再加入后续畸形/不支持内容；允许保留安全前缀，但 total/revision 只来自稳定完整扫描。分别核对扫描、请求页、展示与引用捕获完整性及排除范围。
5. 只选择已就绪的确切 OPS 官方替代项；read 要求 inspect_local_file，不能用 read_files 代替。同名外来工具不能满足就绪条件。

## 权限、运行时与卸载

分别测试只读、工作区写与完全权限。凭据保护读取须拒绝；只读模式拒绝写入，工作区写模式拒绝越界写入，不泄露被拒路径/内容且不改文件；完全权限遵循其较宽的写入授权。宿主允许的普通外部读取是允许对照，并非“工作区读取沙箱”失效。权限变化、取消和卸载须停止或失效自身工作，仅撤回本插件注册。

Bash 保留宿主 command/description/cwd/timeout 契约、审批、jobs 与输出类型；默认120秒，上限600秒。无 jobs 时不公开后台选项；有 jobs 时通过宿主工具收集或停止，超时提升不能再次执行命令。Windows 受限模式仍有文档注明的部分约束与精确 MSYS 兼容要求。

运行时管理先显示计划，再显式执行；启动后取消可能影响未知。Git/managed 选择仅改草稿，保存后生效。PowerShell 升级针对标准宿主安装，要求重启，并提示操作者检查自定义 pwshPath。不能因打开页面或传输断开而宣称安装成功。

兼容 dsh-TUI 存在时单独记录终端验收；缺少宿主时，相关可选套件必须注明跳过，合成注册测试不能代替真实终端验收。发布审查须保留所有失败与跳过。
